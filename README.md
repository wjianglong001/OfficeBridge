# OfficeBridge · 办公桥

**选几行数据，直接提问；也可以不选，让 AI 自己取数。**

OfficeBridge 是一个直接呈现在表格软件中的 AI 表格处理工具。发送消息时附带当前选区数据，由 Agent 判断是否足以完成任务；数据不够或没有选区时，再按需读取当前工作簿中的相关数据。所有修改先预览再应用。

处理对象可以小到某一个单元格，也可以是一行、一列、一块区域、一张工作表，或整个工作簿。**处理哪里，由用户决定。**

首个宿主是 Windows WPS 表格，后续计划适配 Microsoft Excel。OfficeBridge 连接用户本地的 AI Agent，由 Agent 理解需求和规划操作，由表格宿主提供实际的读写能力。

> 当前版本为 0.12.8。新增 WPS 原生入口包，完整解压后在 WPS 普通“加载项”中选择 XLL，可进入完整办公桥启动流程；原生验证包的侧栏与选区读取已由用户确认，完整后台自动启动及真实 Agent 操作仍需单独实机验收。单元格修改参数在宿主执行前预检，公式漏写等号等错误会返回具体字段，Agent 可在同一轮有限纠正；不自动补等号或放宽公式安全规则。图表排序参数的依赖错误在进入宿主前提示，允许 Agent 在同一轮有限纠正，不再因此使读取失效；普通图表沿用源数据行序，分组排序须显式指定汇总模式。任务根据真实进展判断超时，WorkBuddy 持续思考或准备工具时不再被 120 秒总时限误中断；仍保留无响应与总时长上限。读取参数在进入宿主前预检，允许 Agent 在本轮有限修正；投影数据单独保留原范围尺寸。表格工具失败会展示首次真实错误并停止本轮，保留已应用的前一步；WorkBuddy 的 429 提示不再暗示积分不足。在侧栏选择豆包即可连接，无需单独运行脚本：未运行时自动启动；已运行但接口未开启时，在侧栏确认“重启并连接”，取消则保持原 Agent 对话。所有主动表格操作统一经后台执行模块调度，聊天只展示进度、方案和结果。统计、检查、清洗、方案校验和图表计算在 Worker 中运行；宿主分段读取数据，修改先预览再应用。侧栏直接显示实时选区，完整选区值随消息提供，由 Agent 判断并补充取数。支持 Codex、WorkBuddy 和豆包 Windows 实验适配，共用 17 个工具，保留 512 KB 体积预算。验证边界见 [表格操作说明](docs/table-operations.md)。

## 核心体验：直接提问，按需定位

目标流程是：

```text
选区数据随消息发送（可不选） → AI 判断是否够用 → 必要时补充取数 → 查看结果或修改预览
```

数据读取在后台完成，用户无需先点击“读取数据”。工具应展示本次处理的文件、工作表和范围，让用户随时知道指令作用在哪里。

### 用户选择处理范围

以下是目标交互与任务示例，不表示当前版本已支持全部操作。

| 处理范围     | 用户如何选择             | 可以提出的要求                                 |
| ------------ | ------------------------ | ---------------------------------------------- |
| 某一格       | 点击单元格               | “解释这个公式”“把这里的日期改成指定格式”       |
| 某一行或多行 | 选择行或行内区域         | “检查这条记录缺了什么”“核对这些订单”           |
| 某一列或多列 | 选择列或列内区域         | “统一这一列的日期”“给这列反馈分类”             |
| 一块区域     | 拖动框选                 | “计算这块数据的合计”“标出重复项”               |
| 当前工作表   | 在对话中指定“当前工作表” | “按机构统计成功数和失败数”“整理这张表的格式”   |
| 整个文档     | 在对话中指定“整个工作簿” | “合并各工作表的明细”“检查整个文件中的公式错误” |

这里的“整个文档”指当前工作簿及其中的工作表。工作表和整个工作簿可在对话中直接指定，用户无需手工拖选所有数据。

输入框左下角直接显示当前选区，例如 `Sheet1!A2:D20`，随鼠标选择更新，不可点击切换模式。发送时固定本轮选择并附带全部选区值；移动光标不会改变已发出的任务，任务结束后继续显示实时选择。没有单元格选区或选区完全空白时不附带内容，由 Agent 按问题定位数据。默认光标不限制任务只能处理一格。选区数据够用时可直接分析；不足时补充表头、其他列、公式或同文件中的工作表，无需重新框选。补充读取不代表可以修改无关数据；“这些行”等指代以本轮选区为准。历史上下文继续由 Agent 管理。

### 既能分析，也能执行表格操作

目标能力围绕用户正在做的工作展开：

- **分析与汇总**：计数、求和、分组、比较、解释公式和数据。
- **整理与清洗**：处理空格、重复、日期、数字格式，以及文本拆分和提取。
- **计算与填充**：生成公式、填充行列、补充结构化字段。
- **匹配与核对**：关联多张表，找出缺失记录和数据差异。
- **格式与呈现**：设置单元格样式、标记问题、生成汇总表和图表。

只需回答的问题在侧栏展示结果；需要生成或修改数据的任务，应在明确的目标位置呈现结果。写入时要能看清修改了哪些内容，并提供恢复方式。

当前已提供统计、检查、去首尾空格、范围内写值与常见公式、数字格式/加粗/填色、新增结果工作表、整行/整列增删、已有表改名、原表筛选，以及折线/柱形/条形/饼图。需要修改时，所选 Agent 先生成方案，用户点击消息中的“应用”后由 WPS 执行并回读验证。跨工作簿写入、原生排序及高级图表仍待实现。

列操作可以直接对话，例如“在选区右侧新增一列，表头为测试，其他行填测试成功”“在第二列前插入两列空列”“删除选中的列”。预览显示绝对列位置和影响范围，点击应用才执行；可从菜单恢复最近一次操作。每轮处理一块连续的 1–20 列，新列可同时填写表头和选区内的数据；删除影响整列所有行。此版要求只打开目标工作簿，完整恢复基线按 512 KB 体积校验，不再设置固定单元格数量上限；暂不处理保护、合并、表格/透视表和图形等复杂结构。详细限制见 [列操作规格](docs/table-operations.md)。

也可以直接说“删除选中的行”“在选区末尾插入两行”“把当前工作表改名为整理结果”“只显示生成失败的记录”“根据月份和销售额生成折线图”。行操作单次 1–100 行，影响所有列；筛选和图表将选区首行作为表头，图表仅引用选区中的分类与数值列，不复制或改写原数据。清除筛选、恢复表名、撤销新增图表都沿用菜单中的“恢复本次修改”。原表筛选要求定位完整筛选范围；已有其他范围筛选或手动隐藏行时会明确提示。

## 产品原则

1. **工具在表格里可见。** 从办公软件内打开，围绕当前文件使用，结果能与表格对应。
2. **用户决定目标，Agent 判断数据是否足够。** 选区随消息提供，缺少的数据按需补充；读取参考数据与实际修改位置分别展示，执行前核对目标。
3. **操作直观、步骤简单。** 选择对象后直接输入要求；读取、通信和工具调用由后台完成。
4. **结果可以检查。** 分析说明数据范围与计算口径，修改说明影响位置，失败时清楚反馈。
5. **保留表格的工作方式。** 结果应便于继续编辑、计算和整理，支持后续连续操作。
6. **复用用户已有 Agent。** OfficeBridge 负责宿主连接与操作执行，Agent 负责理解、规划、认证和模型调用。

一个侧栏对话对应一个所选 Agent 的原生会话，连续发送只追加新一轮交互；点击“新对话”或切换 Agent 时创建新会话。上下文与历史压缩由 Agent 管理，插件不截取、拼接或补传聊天历史，也不续接用户在其他客户端的对话。切换失败保留原对话，不把历史移交另一个 Agent。每次发送固定本轮文件和授权范围，手动发送附带完整选区值，自动续办只传新描述；补充值、公式和格式按需读取。最近一次应用、放弃或恢复状态作为宿主反馈一并传入。多步骤任务可登记应用后的下一步：应用成功后带真实结果自动续接同一会话；新方案仍需再次点击应用。失败、放弃、停止或切换文件时暂停，不自动重试。修改方案绑定本轮任务和工作簿完整名称，切换文件或原内容被编辑时拒绝应用。

当前会话保留在 Agent 进程内存中，关闭侧栏或服务后不保证恢复。会话丢失会明确提示开启新对话，不会自动换会话或重发要求。停止仅中断本轮；确认中断完成后可以在原会话继续。

**不再设置固定单元格数量上限**，仍保留 **512 KB、50 个范围** 及宿主物理行列边界。初次发送描述无需扫描所有数据；后续查询、单轮读取缓存和修改快照各按体积检查，超限明确报错，不采样或截断。每轮最多 32 次宿主工具调用，单次等待最长 30 秒；停止后拒绝迟到结果。当前选择支持一块连续区域；行列模式按 UsedRange 的相应维度裁剪，工作表和工作簿模式用各表 UsedRange 确定边界，内容仍按需读取。UsedRange 可能包含残留格式。结构恢复基线另受 512 KB 预算约束，只有调用对应结构工具时才准备。

写入限于本轮已定位并预览的目标，结果可输出到新工作表，不覆盖同名表。同一轮同一工作表只支持一个写入区域，可读取多个参考区域。公式仅支持经过校验的常见英文函数和当前表内引用，外部数据函数、跨表公式、合并单元格及数组公式修改暂不支持。应用失败会尝试恢复并核对，无法完整恢复时明确列出位置，不显示成功。应用和恢复均不自动保存工作簿。

## 快速开始

当前使用需要 Windows WPS，以及已安装、已登录的 Agent。OfficeBridge 的 exe 包含自身运行时，不包含 WPS 或 Agent；WorkBuddy 使用其桌面包自带的 CLI 和运行时；豆包实验适配连接已启用的仅本机客户端接口，见 [接入说明](docs/doubao.md)。

### 方式一：在 WPS 中选择原生加载项

完整解压 `release/wps-native/OfficeBridge-WPS-0.12.8.zip`，保持 `OfficeBridge` 文件夹中的 XLL、`OfficeBridgeService.exe` 和许可文件在一起。在 WPS 表格进入 **工具 → 加载项 → 浏览**，选择 `OfficeBridge.xll`，勾选并确定；使用普通“加载项”，不要选择“COM 加载项”。构建目录中的对应文件为 [OfficeBridge.xll](release/wps-native/0.12.8/OfficeBridge/OfficeBridge.xll)。

如出现 WPS 的“信任并安装”，由用户确认。原生入口核验同目录后台后，通过普通进程创建启动固定的 `OfficeBridgeService.exe`，健康检查通过后打开完整侧栏；无需另找启动脚本或安装 Node.js/npm。已运行的兼容后台可直接复用。该流程不使用 `OAAssist.ShellExecute`，系统拒绝启动时显示真实错误码，不自动重试。

从 **办公桥 → 打开办公桥** 进入后，可处理自己的工作簿，沿用按需读取、Agent 原生会话、修改预览和点击应用的完整流程。关闭 WPS 不保证后台同步退出，不要在使用期间移动或删除该版本目录。

**验收边界：** XLL 验证包的侧栏与读取已通过用户实测；完整包的 WPS 冷启动、实际 Agent 任务和写入仍需实机验证。开发者直接启动的后台、复用已有后台，以及独立烟测都不能证明 WPS 自动启动已完成。

### 方式二：双击 Windows exe

从构建产物目录 `release/` 获取 [OfficeBridge.exe](release/OfficeBridge.exe)，双击即可启动，无需安装 Node.js 或 npm。

程序自动打开 WPS 安装页面。首次使用时，在 OfficeBridge 行点击安装，确认 WPS 信任提示；保存文件后重新打开 WPS 表格。已安装过加载项时，启动程序后即可在 WPS 中打开办公桥。

**保持程序窗口运行**，关闭窗口或按 Ctrl+C 会停止服务。这一版是带控制台的便携程序。重复启动会复用同端口已运行的兼容 OfficeBridge 服务，其他程序占用端口时会提示错误。

`release/` 是生成目录，不随源码提交；可通过下方命令自行打包。CI 配置也会上传名为 `OfficeBridge-windows-x64` 的构建产物。

### 方式三：通过 npm 启动

需要 Node.js 22.16+（推荐 24 LTS）和 npm，在项目目录执行：

```powershell
npm install
npm run dev
```

也可以构建后运行：

```powershell
npm run build
npm start
```

默认服务地址为 <http://127.0.0.1:4318>。浏览器可查看开发预览，读取真实表格需要从 WPS 加载项内打开。

### exe / npm 入口的加载项安装

采用上述原生入口时不需要先打开浏览器安装页。exe / npm 服务启动后，用 Edge 或 Chrome 打开：

<http://127.0.0.1:4318/wps/install.html>

允许浏览器拉起 WPS，确认 OfficeBridge 行状态正常，点击“安装”，并确认信任提示。保存文件后重开 WPS 表格，从 **OfficeBridge → 打开办公桥** 打开侧栏。

安装由用户在页面点击完成，OfficeBridge 不自动修改 WPS 安装目录或用户加载项配置。完整步骤、卸载和故障定位见 [WPS 安装说明](docs/wps-install.md)。

### 使用当前版本处理表格

1. 在 WPS 中选择要处理的几行、几列或单元格，左下角会显示当前选区；也可以直接提问，由 Agent 自行定位取数。
2. 在底部输入框输入要求，例如“去掉这列文本两端的空格”“把重复项标黄”“按机构生成统计表”。点击右下角发送，或按 Enter；Shift+Enter 换行。
3. 在同一条对话中查看 Agent 回复、修改预览和执行结果。涉及修改时，展开明细后点击消息下方的 **应用** 或 **放弃**。
4. 多步骤任务应用成功后自动获取下一步预览，无需输入“继续”；失败、放弃或停止时暂停。仍可直接追问；右上角菜单可选择 Codex / WorkBuddy / 豆包（实验），也提供新对话、恢复上次修改和重新连接。切换 Agent 会开启新对话。生成期间，右下角发送按钮变为停止按钮。

主界面只保留消息流和输入框，不需要单独读取数据。Agent 可在本轮允许的工作表内定位，参考数据范围可在回复下方展开查看；有歧义时在聊天里选择即可继续同一会话。运行期间移动光标不改变本轮目标，修改需点击应用。

修改明细最多展示前 100 项，新增结果表展示前 10 行预览，应用仍包含完整方案。打开侧栏仅检测接口和创建会话；发送消息和应用成功后的自动续办会使用模型额度。自动链最多续办 8 轮，达到上限明确暂停。

首次应用前建议在副本中验收。保存文件后重开 WPS 或重新打开侧栏加载新版脚本；无需重复安装同一地址的加载项。恢复只针对最近一次应用，关闭侧栏后记录丢失，后续被编辑的目标会拒绝恢复；不依赖宿主原生 Ctrl+Z。

## Agent 与本机配置

当前使用所选 Agent 已有的登录和模型配置，OfficeBridge 不单独管理模型 API Key。

若未找到 Codex，可设置 `OFFICEBRIDGE_CODEX_PATH` 指向原生可执行文件后重新启动。Windows 下也会尝试定位 VS Code 的 OpenAI 扩展自带的 `codex.exe`。若提示未登录，请通过 Codex 自身的登录方式登录，再点击侧栏右上角菜单中的“重新连接”。

WorkBuddy 会从常见目录和 Windows 注册表发现桌面安装。若未找到，可设置 `OFFICEBRIDGE_WORKBUDDY_PATH` 指向 `WorkBuddy.exe` 或 `WorkBuddyAI.exe`，重启桥接后在右上角选择 WorkBuddy。无需单独安装 CodeBuddy CLI；不接管桌面已有会话。真实 ACP 和 7 个表格工具加载已在 WorkBuddy AI 5.3.13 预检，未发送真实模型请求；登录和推理需要实际发送时验收。

本机 Agent 仍可能调用云端模型，选区数据会按其配置交给模型服务处理。本地启动不代表模型和数据处理全程离线。

可选配置：

| 配置                          | 用途                                               |
| ----------------------------- | -------------------------------------------------- |
| `OFFICEBRIDGE_PORT`           | 修改服务端口，默认 4318                            |
| `OFFICEBRIDGE_CODEX_PATH`     | 指定本地 Codex 原生可执行文件                      |
| `OFFICEBRIDGE_WORKBUDDY_PATH` | 指定 WorkBuddy 桌面 exe 路径                       |
| `OFFICEBRIDGE_DATA_DIR`       | 指定 Agent 临时工作目录的父目录                    |
| `--port 4319`                 | 启动参数指定端口，覆盖端口环境变量                 |
| `--open` / `--no-open`        | 是否自动打开安装页面；exe 默认打开，npm 默认不打开 |

例如：`OfficeBridge.exe --no-open`，或 `npm start -- --port 4319 --open`。开发模式可设置 `OFFICEBRIDGE_PORT` 后运行 `npm run dev`。更换端口后需在新地址重新安装/更新加载项。

会话、数据限制和测试边界见 [Codex 接入说明](docs/codex-analysis.md) 和 [WorkBuddy 接入说明](docs/workbuddy.md)。

## 技术结构

```text
表格中的工具界面 ↔ 本地桥接程序 ↔ Agent 适配器 ↔ 用户本地 Agent
        ↓
宿主提供单元格、行列和工作簿读写接口
```

OfficeBridge 负责把用户选择的对象、指令和执行结果连接起来。实际表格操作由 WPS 或后续 Excel 适配层执行，Agent 使用统一工具读取本轮快照并暂存方案，用户应用后由宿主执行。

读取、统计、检查、清洗、生成修改方案、应用和恢复统一经过 `OfficeBridgeExecutor` 串行队列。纯计算通过独立 Worker 回传结果，聊天界面不直接执行表格任务，可在等待时输入草稿或停止。WPS 适配层仍负责原生接口；较长读取/检查分段执行，最后的原生修改、回读和回滚保持同步事务。因此后台执行模块不等于把 WPS 原生调用移到独立进程，宿主本身的长调用仍可能影响界面，真实 WPS 耗时需实机验收。后台线程不可用会明确提示，不在聊天线程静默重算。

```text
apps/
  bridge/src/          本地 HTTP 服务、启动逻辑与资源服务
  wps-addin/           WPS 工具栏、侧栏与宿主适配
  wps-bootstrap/       原生加载项的启动页与完整侧栏入口
packages/
  protocol/src/        宿主上下文、选区和消息契约
  agents/src/          Agent 适配器与受限表格工具
scripts/               构建、打包与 exe 检查
tests/                 桥接、协议与 Agent 测试
docs/                  架构、安装、接入与分发说明
```

当前实现细节见 [架构文档](docs/architecture.md)。

## 开发检查与 Windows 打包

检查源码并构建：

```powershell
npm run check
npm run build
```

`npm run check` 包含类型检查、测试和格式检查。自动测试使用替身，不默认发送真实模型请求。

在 Windows x64、Node.js 24 LTS 环境生成 exe：

```powershell
npm ci
npm run package:win
npm run test:exe
```

产物包括 `release/OfficeBridge.exe`、使用说明、第三方许可和 SHA-256 校验文件。exe 内嵌运行时和 WPS 资源，可放在项目外运行；首次打包需要联网获取对应 Node.js 版本的许可文件。分发时保留配套文件，此构建尚未配置 Windows 代码签名。

生成 WPS 原生入口包并执行独立检查：

```powershell
npm run package:wps
npm run test:wps-package
```

需要本机 Zig 0.13；可向 `scripts/package-wps-native.mjs` 传入 `--zig <zig.exe>`。当前版本目录为 `release/wps-native/0.12.8/OfficeBridge/`，压缩包只包含固定发行文件，不包含用户工作簿或 Agent 配置；新版本不会覆盖旧版本目录。

exe、GUI 后台和原生 API 的独立检查不等于真实 WPS 或模型端到端验证。更多约定见 [分发说明](docs/distribution.md)。
