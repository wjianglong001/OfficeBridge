# XLL 引导最小验证记录

日期：2026-10-23。项目：OfficeBridge。下文保留各阶段原始验证结果；最新进展见末节：最小侧栏与选区读取已由用户确认，完整 0.12.8 包的 WPS 冷启动仍待验收。

## 结论

**本机未通过。** 已验证 WPS 可在“工具 → 加载项 → 浏览”选择、勾选并执行原生 XLL。引导程序在写出内嵌后台的第一段数据时失败：`write_resource / 5`，即 `WriteFile` 返回访问被拒绝。后台端口 43191 未启动，真实侧栏和选区读取未完成，不能宣布“一个文件完成安装”可用。

独立进程使用同样的资源读取、分段写入、SHA-256 校验与重命名流程可以成功。这将问题缩小到 WPS 进程内的写出行为或其运行环境；尚无证据确定是 WPS 自身限制、进程策略还是其他安全软件。未修改权限、安全设置、WPS 安装文件，也未使用外部预释放文件绕过失败。

## 实机证据

- Windows x64，WPS 12.1.0.29161；实际表格宿主 PE Machine 为 `0x014c`，生成 x86 XLL，后台为 x64 Node.js SEA。
- 仅使用 `OfficeBridge-XLL-Probe.xlsx` 临时人工表，框选 B2:C3，包含两段测试文字及 12、34。未读取或修改用户业务表。
- WPS 加载项列表出现实验 XLL，点击确定后确实进入 `xlAutoOpen` 并执行后台引导线程。
- 最后一次 WPS 实测文件：`OfficeBridgeProbe-v3-x86.xll`，SHA-256：`2bd4eb6cf46da84580c31549be12330acdda497bccb0c419c6695b694203ad25`。
- 整块及 32 KB 分段写入均未成功，实际缓存中只产生空临时文件；分段版明确定位为 `write_resource / 5`。
- 对照提取程序在独立 `XllProbeControl` 目录成功提取，并校验出完整后台；没有向 WPS 启动缓存预填后台。
- 测试结束在 WPS 加载项管理中取消勾选全部三个实验入口并确认。条目可能仍列出，模块在退出 WPS 前可能驻留；没有自动修改或删除其他加载项。
- 本次没有成功启动 WPS 路径中的后台，因此没有通过后台注册实验 JS 加载项；没有启动、重启或调用任何真实 Agent。

## 下一步判断

先确定 WPS 进程内写出行为的受支持权限与签名要求，再决定是否继续 XLL 安装路径。不能直接承诺签名即可修复，也不能根据这一台机器断言全部 WPS 版本都不支持。问题解决前保留正式 exe/npm 启动方式，不替换正式分发入口。

官方文档确认的范围是 [Application.RegisterXLL](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Application/member/RegisterXLL) 可加载并注册 XLL；文档本身不能证明释放外部进程和打开 JS 侧栏的整条链路可用。
