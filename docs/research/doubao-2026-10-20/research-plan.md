# 豆包客户端接入 OfficeBridge：调研计划

- 问题：复用 Windows 用户已安装、已登录的豆包，在 WPS 侧栏建立连续会话并调用受限表格工具，现有哪些可行路线？
- 受众：OfficeBridge 项目负责人；输出为有证据的简报，服务后续实现决策。
- 证据截止：2026-10-20；地域：中国大陆；平台：Windows；不将 macOS 验证直接推广为 Windows 支持。
- 模式：单人调研；中等实施决策风险。核对第一方接入文档、开源实现与当前项目代码，产出可复查的事实、推断和未验证项。
- 范围：当前轮只调研、阅读公开源码和已有项目代码、编写调研文档；不重试被拒绝的调试启动操作，不安装连接器、不改变用户配置、不发送模型请求。

## 证据线程

1. 豆包工作/新版电脑版的 MCP、Skill、Plugin、OpenAPI 能力。完成条件：明确谁调用谁、传输和配置方式、开放状态；若发现官方外部会话 API，重新评估实验性方案优先级。
2. 外部程序控制已登录客户端的开源路线。完成条件：确认 Windows 实现、原生会话/任务标识、回复和失败处理、实测范围、版本条件、维护成本。
3. 映射到 OfficeBridge。完成条件：列出可复用组件、缺失桥接部分、与现有权限和会话约束的冲突、最小验证步骤；不把模拟或作者自述当作本机验收。

## 证据和停止标准

优先产品方和连接器提供方文档、仓库作者的 README 和源码。核心结论追溯到已读页面/代码。搜索报道仅作线索。关键事实与操作限制覆盖后停止扩大搜索。最终检查来源池、引用完整性和结论边界。
